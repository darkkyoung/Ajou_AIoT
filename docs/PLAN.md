# HW2 개발 계획서

작성일: 2026-11-25  
제출 마감: 2026-11-30 23:59 KST

## 1. 목표

두 공간의 CO₂와 재실 인원 센서값을 이용하여 5분 후 CO₂ 농도를 예측하고, 기준 초과 전에 환기를 조절한다. AWS IoT TwinMaker와 Grafana에서 공간별 센서값, 예측값, 판단 상태, 환기 출력을 자동 갱신한다. 실제 센서가 아닌 모의 환경을 사용하므로 현실의 실내 공기질 또는 안전성을 입증하지는 않는다.

## 2. 확정 사양

| 항목 | 일반 강의실 | 컴퓨터실 |
|---|---|---|
| 엔터티 | classroom-01 | computerlab-01 |
| Scene | classroom-scene | computerlab-scene |
| 가정 부피 | 180 m³ | 150 m³ |
| CO₂ 센서 | 420–5000 ppm | 420–5000 ppm |
| 재실 인원 센서 | 0–40명 | 0–30명 |
| 생성 주기 | 1분 | 1분 |

총 4개의 센서 입력을 사용한다. CO₂는 환기 필요성을 판단하는 입력이며, 인원은 향후 CO₂ 발생량을 예측하기 위한 입력이다. 환기 출력은 센서가 아니라 제어 변수이다. 외기 CO₂는 420 ppm으로 가정한다. 1000 ppm은 과제용 제어 기준이며 법적 안전 기준이라고 주장하지 않는다.

### 시뮬레이션

한 공간의 90분 시나리오: 정상(0–14분), 혼잡(15–39분), 재실(40–54분), 회복(55–74분), 비재실(75–89분). 초기 농도, 인원, 환기, 작은 확률 변동을 시드로 재현한다. 다음 농도는 발생량과 외기 교환량의 차이로 계산한다.

- C_next = C + 240*N/V - (ACH/60)*(C-420) + noise
- 환기 출력 20/60/100%에 대해 ACH 1.2/3.6/6.0 h⁻¹을 가정한다.
- 240은 모의 CO₂ 발생계수(단위 ppm·m³/(인·분))로, 실제 센서 기반 보정값이 아니다.
- 초기 목표 60회 × 2공간 × 90분 = 10,800개 센서 기록.
- 예측 학습 타깃은 현재 인원과 현재 환기 출력이 향후 5분 유지된다는 가정의 시뮬레이션 결과로 정의한다. 미래 제어값이나 미래 관측치를 입력에 사용하지 않는다. 실제 제어 후 관측값과 개입 전 조건부 예측값은 구분한다.

### AI 및 제어

- Persistence (현재 농도 유지), Linear Regression, Random Forest 비교.
- 입력: 현재 CO₂, 재실 인원, 최근 CO₂ 변화량, 현재 환기 출력, 공간 부피 등 현재 시점에서 알려진 정보.
- 동일한 episode 단위 train/validation/test 분할. 두 공간의 동일 episode는 같은 분할에 두고, 학습/모델 선택/최종 평가를 구분한다. 재현 가능한 시드와 평가 결과를 기록한다.
- MAE, RMSE, R², 기준 초과 예측 성능을 비교하고 배포 복잡성도 고려하여 최종 모델을 선정한다.
- 현재 CO₂ ≥ 1000 ppm: 강화 환기(100%). 현재 < 1000이고 예측 ≥ 1000: 사전 환기(60%). 그 외: 기본 환기(20%).
- 동일 외생 입력(인원 시나리오, 초기값, 노이즈)에서 현재값 기반 제어와 AI 제어를 비교한다. 초과 시간, 초과 농도, 환기 출력 누적량 등을 비교한다. 제어 효과는 모의 환경 결과로 제한한다.
- Lambda 배포는 선형 가중치 JSON 또는 RF 트리 구조 JSON과 순수 Python 추론을 우선 고려한다. 내보낸 모델과 원본 모델의 예측 일치 테스트를 한다.
- LSTM은 필수 기능과 제출물을 확보한 이후에만 추가 후보로 검토한다.

## 3. AWS 구조

EventBridge Scheduler → 생성/추론 Lambda → S3 (공간별 시간순 JSON 및 지속 상태) → 조회 Lambda → TwinMaker → Grafana.

- 두 공간에 별도 Scene 및 엔터티를 만든다. 하나의 대시보드에서 공간별 현재 농도, 예측값, 인원, 환기 출력 및 상태 아이콘/색상 표시.
- 생성 데이터와 판단 결과는 같은 시각 및 공간 ID로 기록한다. 이전 상태를 읽어 환기 효과가 다음 시점에 반영되도록 구현한다. 중복 호출 및 동시 갱신을 고려한다.
- 조회 Lambda는 요청된 공간/속성/시간 범위를 필터링하고 TwinMaker 자료형에 맞춰 반환한다.
- IAM 최소 권한, Grafana AssumeRole, ExecuteQuery 및 S3 CORS를 사전에 점검한다. IAM Identity Center 기존 환경 재사용 여부 확인.
- AWS 리전은 서울(ap-northeast-2)을 우선 사용한다. 리소스 이름은 aiot-hw2 접두어를 사용한다. AWS 생성 전 비용 및 서비스 가용성을 확인하고 사용자가 승인한 계정에서만 배포한다.
- 두 공간 모델은 과제 제공 School Classrooms Asset Pack(styloo, CC0 1.0)을 사용한다. 실제 파일 확보 여부는 별도 확인한다.
